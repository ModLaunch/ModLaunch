# Платежи ModLaunch (Этап 7)

## Сравнение: bePaid или WEBPAY

| | **bePaid** | **WEBPAY** |
|---|---|---|
| Как подключается | REST API (JSON), страница оплаты по токену | HTML-форма с подписью (POST) |
| Подпись уведомлений | RSA-SHA256 по телу запроса, публичный ключ магазина — надёжно | MD5 по полям + секретный ключ — слабее, но приемлемо |
| Возвраты | через API — сервер делает сам | через кабинет / SOAP-API по отдельному запросу |
| Подписки (автосписание) | есть отдельный API подписок | по документации — нет |
| Документация | открытая, на английском и русском | частично открытая; боевой адрес формы и API возвратов — по договору |
| Способы | карты, ЕРИП, рассрочки и др. — по договору | карты, ЕРИП, рассрочки и др. — по договору |

**Рекомендация: bePaid — основной** (лучшее API, автоматические возвраты, надёжная подпись, есть подписки), **WEBPAY — запасной**.
Сервер поддерживает обоих; переключение — одна настройка `PAYMENT_PROVIDER` (`server/README.md`).
Ставки эквайринга, допустимые валюты (BYN, USD, EUR, RUB) и типы карт определяются договором с банком — уточнить при подключении;
в программе нигде не обещаны конкретные платёжные системы.

## Как идут деньги

```
Покупатель ──карта──▶ bePaid / WEBPAY ──▶ расчётный счёт ООО «МодЛаунч» (РБ)
                                  │
                       уведомление (подпись) ──▶ сервер ModLaunch
                                                   ├─ выдаёт покупку (игра в библиотеке / подарок / премиум)
                                                   ├─ пишет чек
                                                   └─ начисляет разработчику (цена − комиссия площадки 0–29 %)
Разработчик ──заявка на выплату──▶ админ переводит с расчётного счёта ООО ──▶ отмечает «Переведено»
```

* Цену платежа считает **сервер** (региональная цена, скидка со сроком), а не программа — подменить нельзя.
* Покупка выдаётся **ровно один раз** (повторное уведомление ничего не дублирует); неверная сумма, валюта или
  тестовый режим — платёж «на проверке», покупка не выдаётся.
* Возврат: покупатель просит в течение 14 дней → админ одобряет → деньги возвращаются (bePaid сам), покупка
  закрывается, заработок разработчика уменьшается.
* Внутренний «баланс ModLaunch» (рубли) из прежних версий остаётся для рынка Creator Hub; новые покупки игр,
  премиум и донаты идут картой напрямую.

## Что сделано

| Что | Где |
|---|---|
| Страница игры: цена в валюте человека, скидка, «Купить», «Подарить» (только другу) | программа |
| Ожидание оплаты, покупка сразу в библиотеке, «Обновить до x.y.z» при новой сборке | программа |
| История оплат, чеки (HTML: реквизиты ООО, УНП, сумма, способ), возврат 14 дней | Аккаунт → Покупки |
| Ключи (выпуск разработчиком, активация покупателем) | программа + сервер |
| Премиум-подписка (месяц/год, продление), донаты автору и ModLaunch картой | программа + сервер |
| Кабинет разработчика: цены BYN/RUB/USD/EUR, скидки, заработок по дням, выплаты | программа |
| Админ: магазин вкл/выкл, комиссия, цены премиума, реквизиты, выплаты, возвраты | Аккаунт → Магазин |
| Тесты: подпись WEBPAY совпадает с примером из документации; 19 сценариев сервера; программа ↔ сервер | `tools/integration.sh` |

## Что нужно сделать вам (не в коде)

1. Договор интернет-эквайринга (bePaid и/или WEBPAY) на ООО — банку понадобится сайт с реквизитами, договором
   публичной оферты, политикой конфиденциальности и правилами возврата (черновики — `docs/legal/`).
2. Тариф Blaze в Firebase, секреты и выкладка сервера — `server/README.md`.
3. Тестовые покупки → только потом `PAYMENT_TEST=false`.
4. Бухгалтерия: учёт выручки и выплат разработчикам (агентская схема или лицензионный договор — решает юрист и
   бухгалтер; от этого зависит НДС и как отражать комиссию).

## Что не сделано

* **Автосписание подписки** (рекуррентные платежи): сейчас премиум продлевается новой оплатой. Подключается через API
  подписок bePaid после согласования с банком.
* **Файлы игр на CDN** (R2): сейчас сборки до 8 МБ — в базе, больше — по ссылке разработчика с проверкой SHA-256.
  План — `docs/release/SCALE-AND-COSTS.md`.
