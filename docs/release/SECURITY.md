# Безопасность ModLaunch (Этап 5) — что сделано и как устроено

## Где проверяются права

ModLaunch работает без своего сервера с данными: всё лежит в Firebase Firestore, а **права, деньги, оценки и
админские действия проверяют правила базы** (`firebase/firestore.rules`) — их выполняет сервер Google, а не
программа. Подделанная программа может отправить что угодно, но база примет только то, что разрешают правила.

| Что | Как защищено | Проверено |
|---|---|---|
| Деньги (кошелёк, покупка, выручка, вывод, донаты, возвраты) | каждое изменение баланса — только вместе с записью журнала, правила сверяют сумму с основанием | 58 тестов правил + 7 попыток «нарисовать деньги» в интеграционных тестах |
| Админские действия | почта в `admins/` + подтверждённая почта | тесты «админ без подтверждённой почты — не админ» |
| Оценки и отзывы | 1–5 звёзд, один отзыв на человека, автор не снимает «скрыто модератором» | тесты правил |
| Лайки, загрузки, подписчики | счётчик ±1 только вместе со своей записью | тесты правил |
| Жалобы, снятия, баны | читает и решает только админ; снятое не купить/скачать/перезалить; забаненный не публикует | 5 тестов правил + 3 интеграционных |
| Всё остальное | `// Всё остальное закрыто` — любая коллекция без правила недоступна | — |

## Секреты в программе

Проверено поиском по всему репозиторию (ключи, токены, пароли, приватные ключи): **секретов нет**.
Единственный ключ — Web API key Firebase (`AIza…`) — по замыслу Google публичный: он только говорит, к какому
проекту обращаться, а доступ решают правила. Рекомендую в Google Cloud Console ограничить этот ключ списком API:
Identity Toolkit, Token Service, Cloud Firestore.

Ключи пользователей (Nexus, AI) хранятся зашифрованными DPAPI на ПК пользователя. Ключи платёжных систем,
VirusTotal и почты — **только на сервере** (`server/`, Secret Manager), в программу не попадают.

## Аккаунты

* Регистрация, подтверждение почты, сброс пароля, удаление аккаунта — работают (интеграционный тест).
* **Защита от перебора**: Firebase режет перебор на сервере (TOO_MANY_ATTEMPTS); программа после 5 неверных
  паролей подряд ставит паузу 30 с, дальше вдвое дольше, до 15 мин.
* **Новый вход**: каждый ПК записывает себя в список устройств. Вход с нового ПК → на остальных «Это вы?»,
  «Нет» → письмо для смены пароля (новый пароль закрывает чужой вход). Письмо о новом входе шлёт сервер.
* **2FA (TOTP)**: код готов. Нужно включить в Firebase Console → Authentication → перейти на Identity Platform →
  Multi-factor → TOTP. До этого пользователь видит «временно недоступна».

## Файлы модов

1. Перед публикацией в Hub и на рынке — чёрный список ModLaunch + **Защитник Windows** на ПК автора.
2. Перед установкой файлов от людей (Hub, рынок, инди-игры) — то же на ПК игрока. Опасное → карантин
   (`%LOCALAPPDATA%\ModLaunch\quarantine`), не ставится.
3. Любой архив из любого источника сверяется с чёрным списком (sha256).
4. Жалоба «Вирус» → очередь модератора → «Снять» с причиной «Вредоносный код»: отпечаток файла сам попадает в
   чёрный список, снятое пропадает у всех за 10 минут.
5. Сервер (`server/functions`, после включения тарифа Blaze) дополнительно проверяет каждый новый файл через
   VirusTotal и сам отправляет опасное в карантин и очередь.

Защитник выключен или стоит другой антивирус → «не проверено», а не «чисто».

## Что выложить/включить (руками)

1. `DEPLOY-RULES.bat` — правила и индексы базы (без этого рынок, донаты, жалобы, баны не работают у людей).
2. Firebase Console → Authentication: TOTP (2FA), «Email enumeration protection» — включить.
3. Google Cloud Console → ключ API → ограничить список API.
4. Создать почту abuse@modlaunchapp.com (см. `docs/legal/DMCA-PROCEDURE.md`).
5. Подпись кода — `docs/release/CODE-SIGNING.md`.
