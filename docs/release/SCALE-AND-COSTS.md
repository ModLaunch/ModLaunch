## 3. Стоимость в месяц

Цены Firestore (Standard): мультирегион ≈ 0,06 $ / 100 тыс. чтений и 0,18 $ / 100 тыс. записей, региональная база
вдвое дешевле; бесплатно 50 тыс. чтений и 20 тыс. записей в день
([Google](https://cloud.google.com/firestore/pricing)). Хранилище R2: 0,015 $ / ГБ-мес, **исходящий трафик бесплатно**
([Cloudflare](https://developers.cloudflare.com/r2/pricing/index.md)). Цены нужно перепроверить в день покупки.

| Статья | 1 000 / день | 10 000 / день | 100 000 / день |
|---|---|---|---|
| Firestore чтения | ~17 $ | ~180 $ | ~1 800 $ |
| Firestore записи | 0 $ (в бесплатной квоте) | ~8 $ | ~90 $ |
| Файлы Hub/рынка **сейчас** (Firestore, ~1,5 МБ/польз./день трафика) | ~6 $ | ~55 $ | ~540 $ |
| Файлы Hub/рынка **на R2** | <1 $ | ~1 $ | ~5 $ |
| Аккаунты (Identity Platform нужен для 2FA: 50 тыс. MAU бесплатно, дальше ~0,0055 $) | 0 $ | 0 $ | ~275 $ |
| Сервер платежей и проверок (Cloud Functions) | <5 $ | ~10 $ | ~30 $ |
| Почта (письма подтверждения, лист ожидания, вход с нового ПК) | 0–15 $ | ~20 $ | ~80 $ |
| Сайт за Cloudflare + мониторинг доступности | ~20 $ | ~45 $ | ~75 $ |
| **Итого (с файлами на R2)** | **≈ 45 $** | **≈ 320 $** | **≈ 2 400 $** (~29 тыс. $/год) |

При 100 тыс. активных в день — около трети годового бюджета (100 тыс. $). Региональная база (europe-west) снижает
главную статью вдвое; переносить существующую базу нельзя (место выбирается при создании) — решать только если
будет новый проект.

## 4. Выдержит ли текущий сервер — что сломается в день релиза

1. **Правила не выложены** → рынок, донаты, жалобы у людей не работают. Выложить `DEPLOY-RULES.bat` до релиза.
2. **Тариф Spark (бесплатный) — критично.** На Spark после 50 тыс. чтений в день база отвечает отказом до полуночи
   по Тихоокеанскому времени. Это ~50 активных пользователей. **До релиза перевести проект на Blaze** и поставить
   бюджетные оповещения (Google Cloud → Billing → Budgets: 100 / 500 / 2000 $).
3. **Резкий старт.** Firestore рекомендует разгонять нагрузку постепенно (правило «500/50/5»: начать с 500 операций/с
   и прибавлять 50 % каждые 5 минут). При резком скачке возможны временные отказы — программа показывает
   «сервис временно недоступен» и повторяет позже. **Решение: пускать людей волнами** из листа ожидания
   (Этап 8: приглашения партиями по 5–10 тыс. в час в первый день).
4. **«Горячие» документы.** Один документ Firestore выдерживает около 1 записи в секунду длительно.
   * счётчик загрузок популярного мода (+1 на загрузку) — при пике часть счётов потеряется, загрузка при этом работает;
   * счётчик продаж игры (+1 в той же записи, что и покупка) — при хите возможны отказы покупок. **Решение в Этапе 7:**
     покупки картой проводит сервер, а продажи считаются по распределённым счётчикам.
5. **Установщик 160 МБ.** 100 тыс. скачиваний = 16 ТБ. Сайт на VPS это не отдаст. Сейчас ссылка в `update.json` и
   на сайте ведёт на GitHub Releases (выдержит). План ниже добавляет зеркало на R2.

## 5. План переезда файлов на CDN (Cloudflare R2)

| Шаг | Что | Когда |
|---|---|---|
| 1 | Установщик и обновления — зеркало `dl.modlaunchapp.com` (R2 + свой домен). `update.json` указывает на R2, GitHub — запасной путь (программа уже умеет: сайт → GitHub). | до релиза, 1 день работы |
| 2 | Файлы новых модов Hub и товаров рынка — в R2. Сервер (Cloud Function) выдаёт подписанную ссылку на загрузку автору и на скачивание — купившему. Отпечаток SHA-256 и проверка Защитником остаются. | Этап 7, вместе с сервером платежей |
| 3 | Перенос уже выложенных файлов (скрипт: куски из Firestore → R2, в карточке ссылка вместо кусков). | после шага 2 |
| 4 | Сборки инди-игр (ГБ) — только R2, скачивание кусками с докачкой (программа уже умеет докачку). | Этап 7 |

## 6. Нагрузочный тест

`tools/loadtest/firestore-load.mjs` ходит к серверу так же, как программа (анонимный вход, настройки, каталог Hub,
витрина, свежие отзывы, запись отзыва), с плавным разгоном и отчётом p50/p95/p99 и кодами ошибок. Боевой проект
нагружать отказывается.

Прогон на локальном эмуляторе (проверка самого теста, 15.11.2026): **1 000 пользователей, 7 200 запросов,
0 ошибок, 1 635 запросов/с, p95 ≈ 130–200 мс** (эмулятор — одна Java-программа на этом ПК, он не показывает
настоящие пределы Firestore).

**Перед релизом (руками):**
1. Создать отдельный проект Firebase `modlaunch-staging` на тарифе Blaze, выложить туда те же правила и индексы.
2. Заполнить его данными (300 модов, 300 лотов) — можно через программу на эмуляторе или вручную.
3. `node tools/loadtest/firestore-load.mjs --project modlaunch-staging --key <web api key> --users 5000 --concurrency 500 --ramp 300`
4. Затем 20 000 пользователей с `--ramp 900`. Норма: ошибок < 0,5 %, p95 < 500 мс. Стоимость прогона — единицы долларов.

## 7. Скорость (замеры 15.11.2026, этот ПК)

| Показатель | ModLaunch 31.0 | Клиент Steam |
|---|---|---|
| Окно на экране, первый запуск на «чистом» профиле | 3,6 с | не замерялся (Steam был запущен, закрывать его не стал) |
| Окно на экране, обычный запуск | **0,9 с** | обычно 5–15 с (по опыту, не замер) |
| Память через 15 с после запуска | **410–460 МБ** | **852 МБ** (запущенный сейчас Steam: 7 процессов) |
| Прокрутка каталога, витрины, главной (время кадра) | **5,3–6,8 мс** (≈150 кадров/с) | — |
| Переход между страницами | 10–150 мс у большинства; медленные: каталог игры 345 мс (первый раз) / 160 мс, настройки «Игры» 295 мс | — |
| Библиотека без интернета | 0,3 с | — |

Как повторить: `powershell -ExecutionPolicy Bypass -File tools\measure-startup.ps1 -Exe out\ModLaunch.exe -Runs 3`,
переходы и прокрутка — `MODLAUNCH_SHOTS=PerfAll ModLaunch.exe --screenshot <папка> --only`.

**Что можно ускорить дальше:** страница каталога игры (1 750 элементов на экране — включить виртуализацию списка) и
настройки «Игры» (2 840 элементов). Оба места не мешают работе, но заметны.
